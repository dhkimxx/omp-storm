# Storm 사용 안내

[설치와 빠른 시작](../README.md) · [설계·개발](design.md)

## 팀과 작업

- `/storm`에서 추천 팀을 그대로 쓰거나 `모델·effort 수정`으로 필요한 자리만 바꿉니다. 각 선택 행에서 현재 모델과 effort를 함께 확인할 수 있습니다. OMP 모델 선택창에서 추천 목록 밖의 모델을 골라도 현재 대화의 모델은 바뀌지 않습니다. 워커 범위나 팀 공통 설정을 바꿀 때는 `역할별로 고르기`를 쓰세요.
- 첫 승인 때 자동 위임을 안내하고 켭니다. 그 전에 끄기로 정했거나 이후 `/storm auto`에서 끄면 그 선택을 유지합니다. 자동 위임이 켜져 있으면 일반 대화는 메인이 답하고, 도구를 쓰는 작업은 팀에 위임합니다. 수동으로 맡길 때는 `/storm <요청>`을 씁니다.
- 팀과 자동 위임 선택은 세션별입니다. 같은 세션을 다시 열면 팀이 돌아오지만, 새 세션·포크는 빈 팀으로 시작합니다. 작업 트리가 바뀌면 같은 팀을 새 대상에서 다시 승인합니다.

| 바로가기 | 용도 |
|---|---|
| `/storm setup` | 현재 세션의 팀 다시 설정 |
| `/storm models` | 더 나은 모델 후보와 새 버전 확인 |
| `/storm reset` | 현재 세션의 Storm 설정과 기록 초기화 |
| `/storm view` | 현재 세션의 실행 중 레인 뷰 켜기·끄기 |

## 실행 중 화면

실행 중에는 입력창 아래에 레인 뷰가 뜹니다. 첫 줄은 단계·이행 수·라운드·워커 수·비용 같은 상태 줄이고, 그 아래 `감독` 줄기가 가로로 지나갑니다. 계획의 레인마다 줄이 하나씩 있어서 줄기에서 갈라져 나왔다가 결과가 수용되면 다시 줄기에 합류합니다. 레인이 화면보다 많으면 끝난 레인부터 접고 `+N 레인` 줄에 상태별 개수를 보입니다. 높이는 그리는 줄만큼이라 마지막 레인 아래에 빈 줄이 없고, 터미널 줄 수의 3분의 1(6~12줄)이 상한입니다. 레인이 적으면 그만큼 낮고, 계획의 레인 수가 바뀔 때만 입력창이 그 차이만큼 오르내립니다. 입력은 평소처럼 되고, 입력하는 동안에는 움직이지 않습니다.

| 보이는 것 | 뜻 |
|---|---|
| 줄에서 빛덩이가 흐름 | 워커가 일하는 중(`작업 중`). 활동이 많을수록 빠릅니다. 1분 넘게 활동이 없으면 `조용`으로 바뀌어 흐름이 잦아듭니다 |
| 줄기에서 줄이 갈라짐 | 레인이 시작함 |
| 점선 | 아직 시작 전(`예약`). 더 성긴 점선과 다른 레인으로 이어진 연결은 선행 결과를 기다리는 중(`선행 대기`) |
| 이중 줄, 초록 `◆` | 결과가 제출됐고(`제출`) 리뷰어가 실행 중이면(`검토 중`) 초록 빛이 오갑니다. 리뷰 레인이 어느 레인에 기대는지 정해 두었으면 그 레인만, 정해 두지 않았으면 제출된 모든 레인이 함께 검토 중으로 보입니다. 리뷰어가 레인별로 무엇을 보는지는 기록에 없어서 이렇게 추정합니다 |
| 줄이 줄기로 올라가 합류하고 초록 `●` | 결과 수용(`승인`). 합류한 레인의 색이 줄기에 한 구간으로 남아, 줄기는 이행이 쌓일수록 무지갯빛이 됩니다 |
| 빨간 번개와 `✕` | 레인이 막힘(`막힘`) |
| 빈 `○`에서 빛이 한 번 튕겼다 다시 흐름 | 미충족 판정 뒤 재시도 |
| `⊘`가 붙은 점선 | 사용자가 제외한 레인(`제외`). 계획에서 빠져도 그 자리에 남습니다 |
| `■`/`□`가 번갈아 채워짐 | 워커가 아닌 정형 작업 |
| 줄기를 가르는 빛줄기와 새 눈금 | 새 라운드 |
| 색이 빠지고 멈춘 채 호박색 `█`만 천천히 깜빡임 | 사용자 응답을 기다림 |
| 줄기에 무지개가 한 번 달리고 레인이 차례로 반짝임 | 범위 안 결과가 모두 수용돼 끝남 |
| 왼쪽부터 어두워지고 빨간 표시만 남음 | 해결하지 못한 일을 남기고 멈춤 |

레인 오른쪽에는 상태 단어가 있고, 결과가 둘 이상이면 `충족/전체`가 붙습니다. 색만으로 상태를 말하지 않고 모양과 밝기가 함께 말합니다. OMP의 모션 설정(`--motion`)이 `reduced`나 `none`이면 움직임 없이 색만 있는 정지 그림이 됩니다.

다음 경우에는 예전처럼 한 줄(단계, 칩, 작은 레이더)만 보입니다: 터미널 폭이 60칸 미만이거나 18줄 미만일 때, OMP의 ASCII 글리프 설정, 네이티브 렌더링 터미널(Tern), OMP가 터미널 화면이 없는 방식(RPC 등)일 때. 실행 중 창을 줄이면 뷰가 한 줄(또는 폭이 좁으면 한 줄만)로 줄고 입력창이 그만큼 내려오며, 빈 줄은 남지 않습니다. 창을 다시 키우면 그림이 돌아옵니다.

`/storm view`는 이 세션의 레인 뷰를 껐다 켭니다(기본은 켜짐). 끄면 한 줄만 보이고, 실행 중에 바꿔도 바로 적용됩니다. 새 세션이나 포크에서는 다시 켜져 있습니다. 그림은 메모리에만 쌓이므로, 재시작한 세션이 실행을 이어 가면 기록에 남은 시작 시각부터 다시 그리고 재시작 전 라운드 눈금은 일부 보이지 않을 수 있습니다.

## 결과 확인과 방향 수정

- 계획이 적용되면 이번에 만들 결과를 알려 줍니다. 라이브 표시(레인 뷰의 상태 줄이나 한 줄)는 이행 수와 현재 결과를, `/storm`의 `전체 현황`은 이행 집계와 결과별 상태·근거·차단 사유를 보여 줍니다. `검토 가능`은 제출물이 있다는 뜻이고, `이행`은 해당 결과의 요건을 충족했다는 뜻입니다. 둘 다 실행 전체의 리뷰·필수 검사 통과를 뜻하지 않습니다.
- 실행 중인 OMP 터미널에서 결과 하나를 빼거나 다시 하라고 명확히 말하면 승인창 없이 조정합니다. 대상이 모호하면 `/storm status`에서 결과 ID를 찾아 `/storm adjust exclude <결과 ID>` 또는 `/storm adjust retry <결과 ID>`를 쓰세요.
- **제외**는 시도하지 않은 독립 레인에 결과가 하나뿐이고 제외 후에도 할 일이 남을 때 적용합니다. 격리 예외나 정형 작업은 대상이 아닙니다. `사용자 제외`는 이행 수에 들어가지 않으며 이미 시작한 일을 끊거나 되돌리지 않습니다.
- **재시도**는 시도가 끝난 미충족 읽기 전용 답변 결과에 한해 다음 시도 한 번을 예약합니다. 계약·경로·입력 버전과 기존 실행 한도는 그대로입니다. 이미 진행 중이거나 재시도 경로가 소진된 경우, 정형 작업인 경우에는 예약하지 않습니다.

### 실행 결과 기록

짧은 자동 조회를 제외하면 실행이 끝난 뒤 대화에 `Storm 실행 결과` 기록이 하나 남습니다.

- **한 줄:** 미해결·사용자 제외·주의 사항 없이 10분 미만에 끝난 실행은 상태·수용 수·소요 시간 한 줄만 남깁니다. 설명은 감독의 평소 응답이 맡고, 고를 방향은 없습니다. 폭 60칸의 터미널에서 한 줄에 맞지 않을 만큼 긴 줄은 `Storm ·` 이름을 빼고 상태 아이콘으로 Storm의 기록임을 보입니다.
- **카드:** 그 밖의 실행은 카드로 남깁니다. 카드에는 요청·대상·소요 시간, 공식 상태와 수용 집계가 있고, 미해결은 원인별 건수로 보입니다. 코드가 기록에서 확인한 주의 사항, 감독 설명, 근거 하나가 이어지고 마지막 줄은 `상세: /storm status`입니다. 공식 줄은 항상 감독 설명보다 앞에 옵니다. 최종 판정 전에 쓴 감독 설명에는 그렇다는 표시가 붙고, 감독 설명은 건수나 상태를 바꾸지 않습니다.
- **다음 방향:** 번호로 고를 수 있는 방향은 최대 3개이며 첫 번째가 추천입니다. 사용자가 직접 할 일은 번호 없이 `직접:`으로 표시합니다. 카드 직후 OMP 터미널에서 번호를 입력하면 해당 작업만 시작합니다. 다른 입력을 하거나 OMP를 재시작하면 번호는 더 이상 동작하지 않습니다. 그때는 `/storm`의 이어 가기나 새 요청을 사용하세요. 고르지 않으면 아무것도 시작하지 않습니다.
- **상세 내용:** 결과별 상태·근거, 감독의 검증 설명, 정형 작업 영수증, 필수 검사 기록, 끝내지 못한 레인은 카드 대신 `/storm status`에서 봅니다.

번호로 고른 새 범위 작업과 이어 가기는 이전 실행 기록에서 최종 사실을 약 1KB로 추려 받습니다. 새 범위 작업에는 이전 판정을 승계하지 않고, 이어 가기에는 현재 근거를 다시 검증한 결과만 남깁니다. 관련 실행을 압축하거나 같은 세션·작업 대상에서 `storm status`로 조회할 때도 이 요약을 사용할 수 있습니다. 상시 프롬프트에는 붙이지 않으며 종료 후 추가 모델 호출이나 캐시 적중이 필요하지 않습니다.

## 중단과 이어 가기

`Esc`로 중단합니다. `/storm` 메뉴에 `끝나지 않은 실행 이어 가기`가 보이면 같은 세션·작업 대상에서 이어 갈 수 있습니다. 현재 파일·출처·보존 산출물로 다시 확인된 결과는 유지하고, 달라진 결과와 그 결과에 의존하는 작업만 다시 엽니다. 종료 여부를 확인할 수 없는 정형 작업은 자동 재실행하지 않습니다.

이어 간 실행의 `/storm status`와 종료 카드에는 그 목표 전체가 쓴 실행 횟수·비용·시간·라운드가 함께 표시됩니다. 예산과 사용자가 말한 한도는 이어 가도 실행마다 따로 적용됩니다.

## 병렬도와 고급 설정

- 새 팀의 탐색·구현 기본 범위는 각각 **1~4명**입니다. 승인된 역할별 최대와 OMP의 `task.maxConcurrency` 안에서 실제 작업에 필요한 만큼만 시작합니다. 쉬던 워커의 재가동도 OMP 상한에 포함됩니다. `0`은 OMP 상한 없음이지, 역할별 제한이나 겹치는 쓰기까지 해제한다는 뜻은 아닙니다.
- 워커는 컨텍스트 크기와 관계없이 후속 지시를 받습니다. OMP가 서브에이전트 세션을 스스로 압축하므로, Storm은 정리로 OMP 기록이 지워진 워커에만 새 워커를 띄우라고 안내합니다. 감독 세션은 모델 창의 50%(실행 시작)와 70%(실행 중)에서만 Storm이 압축하고, 창 크기를 모르면 압축하지 않습니다. 컨텍스트 상한 설정은 없으며, 예전 설정에 남은 `contextCap`은 무시합니다.
- 긴 답변은 길이 때문에 거절하지 않고 리뷰로 보냅니다. 답변은 호스트가 줄인 미리보기가 아니라 워커의 전체 출력으로 판단하고, 전체를 읽을 수 없으면 리뷰로 보냅니다. 출처 값과 다른 숫자를 함께 쓴 자연어 답변도 리뷰로 보냅니다. 리뷰할 수 있는 답변은 같은 라운드에 모두 보내고, 많으면 여러 리뷰 작업으로 나눕니다. 계획 크기 한도는 실제 계획이 걸리지 않을 만큼 넉넉하며, 긴 글은 화면에서만 줄여 보여 줍니다.
- 기본은 같은 작업 트리입니다. 임의 경로에 쓸 수 있는 워커의 공유 작업 트리 쓰기는 순차로 처리합니다. 독립 레인에 분리 체크아웃이 필요하면 계획에서 격리 사유를 밝혀야 하고, OMP 격리를 켜고 자동 적용을 꺼야 합니다. 분리 체크아웃 변경은 부모 작업 트리에 자동 반영되지 않습니다.
- 승인된 팀 설정에 `requiredChecks`를 두면 실제 변경본에서 필수 검사 종료 상태를 확인합니다. 반복 가능한 빌드·변환·측정 명령은 `jobs`로 등록할 수 있습니다. 둘 다 고정 `argv`를 셸 없이 실행하며, 같은 호스트에서 같은 자원을 쓰는 정형 작업은 순차 실행됩니다. 프로세스 종료는 실행 근거이지 측정 결과의 해석이나 검증은 아닙니다. 필수 검사는 `timeoutMs`로 검사마다 제한 시간을 정할 수 있고, 정하지 않으면 넉넉한 기본값을 씁니다.
- 라운드 수에는 기본 한도가 없습니다. 팀 설정의 `rounds`나 요청이 정했을 때만 그 한도를 적용합니다. 변화 없이 끝난 라운드 다음에는 접근을 바꾸라는 지시로 이어 가고, 연속 두 번이면 실행을 끝냅니다. 요청의 시간 제한은 라운드 사이에서 확인합니다. 요청이나 설정이 말한 라운드 수·시간에는 Storm이 따로 정한 최댓값이 없고, 말한 값 그대로 적용합니다. Storm 예산의 비용은 정가 환산이며, 이미 진행 중인 요청 때문에 한도를 넘을 수 있습니다.

직접 설정할 때는 [설정 스키마](../src/config/schema.ts)와 [역할 기본값](../src/roles.ts)을 참고하세요. 설정이 바뀌면 `/storm`에서 다시 승인해야 적용됩니다.

## 저장 데이터

Storm은 팀, 대상별 승인, 자동 위임 선택과 실행 기록을 OMP 프로필의 `<에이전트 디렉터리>/storm/sessions/<세션 해시>/`에 보관합니다. 기본 에이전트 디렉터리는 `~/.omp/agent`입니다. 예전 작업 트리의 `.omp/storm/`은 읽거나 지우지 않습니다.

- `/storm reset`은 확인 후 **현재 세션의 Storm 데이터만** 지웁니다. 실행 중이면 거부합니다. 다른 세션, OMP 대화·설정·API 키와 프로젝트 파일은 그대로입니다.
- 시작과 종료 시점 모두 `실행이 끝나면 정리`가 켜져 있을 때만 이전 Storm 워커의 OMP 기록을 정리합니다. 최근 3개 실행분, 동작 중인 워커와 결과 문서는 남깁니다. `/storm status`의 저장 공간에서 확인할 수 있습니다.
- 이어 가기를 위해 실행 기록에 요청이 들어갑니다. Storm이 별도로 프롬프트·응답 원문을 복제하지는 않습니다.

## 문제 해결

| 보이는 상황 | 먼저 할 일 |
|---|---|
| 승인 필요·설정 오류 | `/storm`에서 현재 대상과 팀 설정을 확인합니다. |
| 동시 상한으로 대기 | 해당 역할의 워커가 끝나는지 봅니다. 전체 동시 상한은 OMP `task.maxConcurrency`에서 조정합니다. |
| 검토 가능·미충족·차단 | `/storm status`에서 해당 결과의 근거와 해소 조건을 확인합니다. 실행 종료 자체를 검증 통과로 보지 않습니다. |
| `/storm <요청>`을 분류하지 못함 | `작업으로 실행`을 선택하거나 대화가 너무 길다면 새 세션에서 필요한 배경만 다시 전달합니다. |
| OMP의 계획·목표·반복·vibe 모드가 켜져 실행할 수 없음 | 해당 모드를 끝낸 뒤 Storm에 맡깁니다. |

## 업데이트와 제거

```sh
omp plugin upgrade omp-storm
omp plugin uninstall omp-storm
```

업데이트 후 열린 OMP에서 `/restart`하거나 OMP를 다시 실행합니다. 제거하면 플러그인은 로드되지 않지만, 세션의 데이터는 `/storm reset`과 별개입니다.
실행 중 방향 수정은 OMP 19.2.1 터미널에서 확인했습니다.
