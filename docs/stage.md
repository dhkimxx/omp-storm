# 동물 무대: 폭풍 속 발광 생물

동물 무대(0.32.0)의 결정과 안무. 지키는 규칙은 [설계](design.md#동물-무대0320), 사용자 안내는 [사용 안내](usage.md#동물-무대), 스파이크 측정은 [스파이크 S0](spikes.md#s0-동물-무대의-이미지-애니메이션0320)에 있다. 아트를 고치거나 새 종을 넣을 때 이 문서의 표가 기준이다.

## 결정

| 항목 | 결정 |
|---|---|
| 세계관 | 발광 생물. 레인 뷰의 오로라·혜성·비·번개·무지개와 같은 세계 |
| 품질 범위 | 이미지 터미널(T1)에서 고퀄, 그 밖은 같은 연기를 저해상도로 |
| 무대 크기 | 폭은 터미널의 30%(28~48칸), 최소 5줄. 레인 뷰 높이 상한(터미널의 1/3, 6~12줄)이 먼저 |
| 제작 | 개체 단위 키프레임. 에이전트가 SVG로 키 포즈를 그리고, 코드는 개체 수·위치·재생 시점만 정한다 |
| 끄기 | 따로 두지 않는다. `/storm view`가 레인 뷰 전체를 끄고 켠다 |
| 아트 크기 | 배포되는 구운 결과(`index.json` + 시트) 4 MiB, 시퀀스 하나 96 KiB, 종마다 600 KiB 목표. 원본(`assets/stage/src`)은 배포하지 않는다 |

## 원칙

1. **무대는 실행 기록을 읽은 결과다.** 종(동물)은 현재 라운드의 모양을 기록에서 계산한다. 감독은 종을 고르거나 선언하지 않고, 무엇도 무대 때문에 바뀌지 않으며, 무대는 저장되지 않는다.
2. **워커 하나가 개체 하나다.** 문어의 팔 하나, 벌 한 마리, 개미 한 마리, 범고래 한 마리가 레인 하나다. 계획 밖 워커도 개체다. 감독은 그 종의 중심 개체다(문어 몸통, 벌집, 개미의 구조물, 범고래의 대상, 올빼미).
3. **연기는 원장의 사건에서만 시작한다.** 수용 연출은 수용이 기록됐을 때만, 피날레는 모든 결과가 충족됐을 때만 나온다.
4. **사실은 글자가 맡는다.** 레인 이름과 상태 글자는 오른쪽 그래프에 지금처럼 남는다. 색만으로 의미를 전하지 않는다.

## 화면

- **무대:** 터미널 폭 89칸 이상에서 레인 뷰 왼쪽. 폭은 터미널 폭의 30%(28~48칸), 상태 줄 아래로 최소 5줄(그림 4줄 + 문구 1줄). 무대가 있는 동안 레인 뷰는 최소 6줄이다(그리는 줄이라 빈 줄 채우기가 아니다). 높이는 지금처럼 드문 사건에서만 바뀐다. 개체 상자는 그림 안에 들어오게 자리를 잡는다.
- **레인 그래프:** 오른쪽, 지금 레인 뷰를 폭만 줄여 둔다. 개체 색은 그 레인 색이라 둘이 짝지어진다.
- **무대의 층:** 날씨(비는 병렬 작업량, 바람은 activity, 번개는 거절·막힘, 무지개는 모든 결과 충족) / 배경(종별) / 개체 / 조각(결과 ID 하나가 빛 조각 하나).
- **개체 수 상한:** 무대 폭에 따라 6~8개. 나머지 레인은 무리 구름과 `+N`으로 묶는다.

## 렌더링 단계

| 단계 | 조건 | 표현 |
|---|---|---|
| T1 | 이미지 프로토콜(kitty 계열, iTerm2). 역할 페인터가 받은 `pi-tui` 이미지를 쓴다 | 실제 픽셀(칸당 9×18), 프레임마다 한 장 합성한 256색 PNG. 목표 품질 |
| T2 | 트루컬러, SSH, `allow-passthrough`가 꺼진 tmux, 움직이는 SIXEL | 반블록 셀 픽셀(칸마다 색 2개). 같은 연기를 저해상도로 |
| T3 | 256색 | 점자 캔버스와 문구 |
| T4 | RPC, Tern, 좁은 화면, `/storm view` 꺼짐의 한 줄 | 한 줄 문구 `문어 · 일을 나눠 맡기는 중` |

- 모든 단계가 같은 장면(개체, 시퀀스, 프레임, 위치, 조각)을 쓰고 래스터화만 다르다.
- SSH는 기본 T2다(지금도 SSH에서 틱을 85ms에서 120ms로 늦춘다).
- 모션이 꺼져 있으면 단계와 상관없이 종과 상태가 드러나는 정지 프레임 한 장만 그린다.

## 종 고르기

매 프레임 레인 뷰 입력에서 계산한다. 위에서부터 처음 맞는 줄이 이긴다.

| 순서 | 기록 조건 | 종 | 문구(15자 이내) |
|---|---|---|---|
| 1 | 단계가 `waiting-user` | 지금 종 유지, 응답 대기 자세 | `응답을 기다리는 중` |
| 2 | 단계가 `stopping` | 지금 종 유지, 완료 자세 | `마무리 중` |
| 3 | 실행 시작, 이어 가기, 재계획(레인 집합 변화) | 찌르레기 한 번 | `팀을 모으는 중` |
| 4 | 도는 레인 가운데 `reviewing`이 있음 | 범고래 | `검토하는 중` |
| 5 | 정형 작업이 돌거나, 범위를 좁힐 수 없는 쓰기가 하나 돌고 쓰기 차례를 기다리는 레인이 있음 | 개미 | `하나씩 처리하는 중` |
| 6 | 도는 레인이 모두 읽기 | 꿀벌 | `여러 갈래 조사 중` |
| 7 | 읽기와 쓰기가 섞여 둘 이상 돎(격리 구현자 여럿 포함) | 문어 | `일을 나눠 맡기는 중` |
| 8 | 도는 워커가 없고 감독 차례만 진행 | 올빼미 | `직접 들여다보는 중` |

- 이전 종이 3초 넘게 있었으면 정식 넘겨주기, 3초 미만이면 0.25s 크로스페이드로 바꾼다. 같은 규칙이 깜빡이는 전환을 막는다.
- 레인 의도(`read`, `write`, `review`, `job`)는 계획 레인의 종류와 계획 밖 워커의 역할·도구 범위에서 정한다. 표시용 단어(`label`)로 판정하지 않는다.
- 문구는 기록이 증명하는 말만 쓴다.

## 공통 연기 문법

| 기록 상태 | 몸짓 방향 | 리듬 |
|---|---|---|
| 차례 대기(`reserved`, `waiting`, G1 순서 대기) | 제자리 준비 동작, 앞으로 나아가지 않음 | 느린 호흡 3.4s |
| 작업(`running`) | 종의 고유 반복 동작, activity가 높을수록 빨라짐 | 1.6~2.4s 루프 |
| 조용함(`quiet`) | 한 자리에서 세밀한 손놀림 | 진폭 절반 |
| 제출(`submitted`) | 조각을 감독 쪽으로 들어 보임 | 1회 강조 후 유지 |
| 검토 중(`reviewing`) | 다른 개체가 조각을 훑음 | 스캔 주기 2.9s |
| 수용(`accepted`) | 조각이 중심 결과물에 끼워지고 빛이 퍼짐 | 합류 폭발과 같은 시각 |
| 미충족(`unmet`) | 조각이 튕겨 나가고 다시 잡으러 감 | 0.6s |
| 막힘(`blocked`) | 그 개체만 굳고 붉은 테두리, 감독 개체가 그쪽을 봄, 나머지는 계속 | 번개와 같은 시각 |
| 제외(`excluded`) | 접히거나 물러나 흐려짐 | 0.8s 후 정지 |
| 응답 대기(`waiting-user`) | 모두 정지, 감독 개체가 정면을 보고 호박색 눈빛 | 호박색 깜빡임 2.4s만 움직임 |
| 완료, 모두 충족 | 종의 피날레 후 쉬는 자세, 무지개 | 2.2s |
| 완료, 남은 결과 있음 | 피날레 없이 남은 조각을 든 채 바라보며 소등 | 4s |

- 호박색은 응답 대기, 빨강은 막힘, 초록은 수용에만 쓴다. 개체 색은 레인 색, 감독 개체는 얼음 파랑이다.
- 라이트 테마에서는 짙은 실루엣과 림라이트로 그리고, 명도는 효과 문서의 OKLCH 규칙을 따른다.

| 종 | 구성 | 작업 | 고유 장면 | 피날레 |
|---|---|---|---|---|
| 문어 | 몸통, 눈 둘, 레인마다 팔 하나(최대 8) | 팔 끝이 작업대에서 조각을 감았다 펴며 빚음, 몸통은 거의 정지 | 분배: 조각을 쪼개 팔마다 건넴 / 막힘: 그 팔만 굳고 몸통과 눈이 돌아봄 / 수용: 조각을 몸통의 결과 구슬에 끼움 | 구슬을 들어 올리고 팔을 가지런히 접음 |
| 꿀벌 | 벌 한 마리가 레인, 감독은 벌집, 꽃이 출처 | 꽃을 정찰하고 빛 꽃가루를 모음 | 제출: 벌집 앞 8자 춤 / 막힘: 바람에 막혀 버팀 | 조각이 벌집 칸에 레인 색으로 들어가고 한 바퀴 돈 뒤 착지 |

| 범고래 | 범고래 한 마리가 레인, 수면선 | 대상 둘레를 나란히 돌며 약 6s마다 선두 교대 | 반려: 간격을 벌리고 다른 개체가 선두로 / 수용: 수면 위로 뛰어오름 | 나란히 정렬해 물결을 남기며 전진 |
| 올빼미 | 감독 단독, 밤 숲 가지 | 4s 주기로 머리를 기울이며 조각을 응시 | 감독 직접 편집: 발톱으로 조각을 고쳐 쥠 / 응답 대기: 정면, 눈을 크게 뜸 | 고개를 짧게 끄덕임 |
| 찌르레기 | 점 60~120개, 전환 전용 | — | 시작: 흩어진 점이 감독과 레인 수만큼의 무리로 / 재계획: 개체가 점으로 풀렸다 다시 모임 / 이어 가기: 수용된 조각이 빛 점으로 남고 새 무리가 그 둘레로 모임 | — |

## 사건 연기

| 사건 | 연기 | 우선순위 |
|---|---|---|
| 응답 대기 시작 | 진행 중인 연기를 끊고 정지, 정면 응시 | 1 |
| 거절, 막힘 | 번개, 해당 개체 굳음, 감독 개체 움찔 | 2 |
| 수용 | 종별 수용 동작과 합류 폭발 | 3 |
| 미충족, 사용자 정지(0.32 I4) | 튕김 / 조각을 내려놓고 무대 밖으로 | 4 |
| 제출, 사용자 직접 지시(0.32 I2) | 들어 보이기 / 개체가 잠깐 정면을 보고 끄덕인 뒤 작업 | 5 |
| 레인 시작, 예산 경고선 | 분배 / 무대 조명 한 단계 낮춤(호박색 아님) | 6 |
| 라운드 넘김 | 라운드 닦기 막대가 무대도 지나감 | 8 |

- 큰 강조는 1.5s에 하나만 튼다. 같은 종류가 0.5s 안에 몰리면 한 번에 합친다.
- 전환 중에 온 사건은 전환 뒤에 재생한다. 응답 대기만 즉시 끊고 들어간다.
- 워커 간 메시지 연출(범고래 음파)은 협업 기능이 들어올 때 더한다. 이번 범위에 없다.

## 종 전환

| 전환 | 장면 |
|---|---|
| 꿀벌 → 문어 | 벌들이 조각을 내려놓고 날아오르면 물이 차오르고 문어 팔이 하나씩 집음 |
| 문어 → 개미 | 문어가 조각을 한 줄로 놓고 물러나면 장면이 흙 단면으로 가라앉고 개미 행렬이 가져감 |
| 개미 → 범고래 | 쌓은 구조물이 물에 잠기고 범고래들이 둘레를 돎 |
| 범고래 → 문어 | 반려된 조각을 범고래가 문어 팔로 밀어 줌 |
| 아무 종 → 올빼미 | 개체들이 나가고 조명이 낮아지며 올빼미가 남은 조각을 내려다봄 |
| 올빼미 → 아무 종 | 올빼미가 날개를 펴 조각을 다음 종 쪽으로 떨어뜨림 |
| 재계획, 이어 가기 | 찌르레기 |

조각(결과 ID)의 위치와 색은 전환을 건너 이어진다.

## 키프레임 제작

- **단위:** 개체 하나의 시퀀스. 종마다 감독 개체와 레인 개체의 상태 루프, 사건 연기, 피날레, 전환. 장면이 요청할 수 있는 시퀀스 전체는 `requestableSequences(species)`(`src/view/stage/scene.ts`)이고, 테스트가 `assets/stage/index.json`이 그것을 모두 담는지 확인한다.
- **저작:** 종마다 생성기(`scripts/stage/art/`)가 SVG 키 포즈와 시퀀스 JSON을 `assets/stage/src/<종>/`에 쓴다. 한 시퀀스 안에서는 키 사이에 숫자만 바뀌고(경로 위상 고정), 그 사이는 감속·가속 곡선으로 보간한다. 보간은 저작 데이터이지 물리 시뮬레이션이 아니다. 형식과 그리는 규칙은 `assets/stage/src/README.md`에 있다.
- **굽기:** `bun scripts/stage/bake.ts`가 보간·래스터화(`@resvg/resvg-js`, 개발 의존성)해 T1(칸당 9×18px)과 T2(반 칸당 1px) 회색조+알파 시트와 `index.json`을 쓴다. 결정적이고 상한을 넘으면 실패한다. 구운 결과는 저장소에 넣고 배포한다. `index.json`에는 시퀀스마다 원본(JSON과 키 SVG)의 sha256(`source`)과 굽기 도구(`bake.ts`·`png.ts` 내용 해시, resvg 버전, `baker`)가 적힌다. `bun scripts/stage/bake.ts --check`는 렌더링 없이 이 해시를 지금 원본과 비교하고 시트가 모두 있고 상한 안인지 본다. 굽지 않은 원본, 바뀐 원본, 사라진 원본, 바뀐 굽기 도구를 이름과 함께 실패로 알린다. `npm run verify`(CI)가 이것을 돌린다. 시트 바이트를 다시 구워 비교하지 않는 까닭은 resvg의 안티에일리어싱이 플랫폼마다 1비트씩 다를 수 있어서다.
- **런타임:** 장면이 개체 스프라이트를 배치하고, 프레임마다 한 장으로 합성해 레인 색으로 칠한다(`raster.ts`). 문어 팔의 연결 곡선, 찌르레기 무리의 자리, 배경 와이프는 장면 코드가 그린다. 구워지지 않은 시퀀스는 아무것도 그리지 않는다.

## 성능과 크기

- 프레임당 CPU 2ms 이하. `bun scripts/stage/qa-bench.ts`가 28/40/48칸 × 5/8/12줄에서 잰다(0.32.0에서 최악 p95 1.83ms).
- T1 전송은 프레임당 32 KiB, 초당 400 KiB. 넘으면 프레임 간격을 최대 4배까지 늘리고, 그래도 넘으면 T2로 내린다.
- 아트 크기 상한은 위 결정 표대로다.
